# 다음 에이전트 작업: 단계 0만 수행

아래 지시를 에이전트의 실행 프롬프트로 전달한다. 이 파일 자체는 작업을 자동 실행하지 않는다.

---

이 저장소의 `AGENTS.md`, `README.md`, `docs/architecture.md`, `docs/issues/00-architecture.md`를 읽고 단계 0을 구현하라.

## 목표

C++ 학습 6개월 학생이 전체 모듈의 책임과 호출 관계를 설명할 수 있도록 **구조 문서와 호출 순서가 보이는 작은 실행 골격**을 만든다. 이번 작업은 엔진 전체 구현이 아니다.

## GitHub 작업

1. 현재 원격이 사용자에게 승인된 새 학습 저장소인지 확인한다. 기존 Nereides 저장소에 push하지 않는다.
2. 단계 0에 해당하는 실제 이슈를 찾고, 없으면 초안 내용으로 작성한다. 제목이 같거나 목적이 같은 이슈를 중복 생성하지 않는다.
3. 실제 이슈에 연결된 작업 브랜치가 있으면 재사용한다. 없으면 `codex/issue-<번호>-architecture` 브랜치를 만든다.
4. 구조 문서, 코드 골격, 실행 안내를 작성·검증하고 작업 브랜치를 push한다.
5. 이슈를 연결한 draft PR을 만든다. 자동 병합하거나 단계 1을 연속 실행하지 않는다.

## 작성할 것

- 구조 문서: Application, Scene, GameObject, Component의 책임·소유권·호출 순서를 명확히 한다.
- C++ 콘솔 실행 골격: 정해진 횟수만 실행하고 정상 종료한다. 창·DX11 의존성을 요구하지 않는다.
- Application의 명시적인 단계 함수로 시작한다. Scene·GameObject·Component의 실제 구현과 두 객체 구성은 단계 1로 남긴다.
- 초기화 → 입력 → 시간 → 객체 → 애니메이션 → 충돌 → 렌더 → 종료 순서를 출력한다.
- 입력·시간·객체·애니메이션·충돌·렌더는 실제 구현이 없는 placeholder임을 로그와 문서에 표시한다.
- 세 프레임의 번호와 각 단계 호출 순서를 구분할 수 있게 한다.
- 기본 클래스, 필요한 가상 함수, 기본 컨테이너만 사용한다. 메모리 소유권과 정리 방법은 안전하게 구현하고 짧게 설명한다.
- 빌드·실행 방법을 제공한다. 사용 가능한 C++ 빌드 도구를 확인하고 가장 작은 구성을 선택한다. 빌드 시스템 여러 개를 만들지 않는다.
- PR에 핵심 파일 읽기 순서, 실제 출력 예시, 이해 질문 3개, 변형 과제 1개를 남긴다.

## 금지 범위

DX11 렌더러, 실제 입력 시스템, 고정 tick 구현, 모델 로더, 애니메이션, 충돌 알고리즘, 전투 규칙, 리플렉션, ECS, 범용 RHI, 씬 에디터를 구현하지 않는다. 기존 Nereides 소스·문서를 복사하지 않는다.

## 검증

- 빌드와 실행을 실제로 수행하고 명령과 종료 결과를 기록한다.
- 각 단계 함수가 세 프레임에서 정해진 순서로 호출되는지 확인한다.
- Application이 main의 지역 객체로 만들어지고 정상 종료하는지 확인한다.
- 실제 기능이 없는 stub 로그를 기능 구현 완료로 보고하지 않는다.
- 환경 문제로 실행할 수 없으면 원인과 미검증 범위를 기록하고 성공으로 표시하지 않는다.
