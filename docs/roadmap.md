## 상태를 분리하는 이유

코드 상태는 미착수 / 진행 / 검증 실패 / 검증 완료 / 병합 완료로 기록한다. 학생 이해 상태는 미확인 / 학생 설명 제출 / 피드백 필요 / 담당자 확인으로 기록한다.

자동 테스트가 통과해도 학생 이해는 자동으로 완료되지 않는다. 실제 학생 설명과 담당자의 피드백을 근거로 기록한다. 에이전트는 학생 답변이나 교수 승인을 대필하지 않는다.

## 단계별 운영

1. 초안을 GitHub 이슈로 만들거나 같은 이슈가 있는지 확인한다.
2. 구조·입출력·소유자·호출 시점을 합의된 문서에 기록한다.
3. 해당 이슈용 브랜치에서 작은 구현과 검증을 수행한다.
4. 연결 이슈, 읽기 순서, 검증 증거, 질문과 변형 과제를 담은 draft PR을 만든다.
5. 학생은 자신의 설명과 과제 결과를 남긴다. 교수의 구조 리뷰를 거쳐 병합하는 운영을 권장한다. 실제 병합 권한은 사용자가 정한다.
6. 다음 단계는 별도 할당 후 시작한다. 이 문서가 자동 실행을 예약하지는 않는다.

한 단계의 범위가 커지면 작업을 숨겨 진행하지 말고 이슈 범위를 조정한다. 추가 기능보다 현재 모듈 관계를 설명하고 실행으로 증명하는 것을 우선한다.
