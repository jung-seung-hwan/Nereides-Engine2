# [단계 4-1] 모델 원본 읽기와 공유

## 목표와 범위

glTF 2.0 모델 파일 하나를 읽어 엔진의 메시 원본으로 바꾸고, 여러 객체가 그 원본을 함께 쓰게 한다. 원본의 주인은 새로 만드는 AssetManager다. 스킨 모델은 뼈를 움직이지 않은 기본 자세(바인드 포즈) 그대로 그린다. 파일을 읽을 때 뼈 개수와 클립 개수를 함께 읽어 보고하므로, 4-2가 같은 원본에 재생을 더할 수 있다. 생성·삭제 반영을 tick 끝으로 옮겨, 4-2의 애니메이션 단계와 단계 5의 충돌 단계가 객체를 차례로 도는 도중에 목록이 바뀌지 않게 한다. 선행: 단계 3-3.

범위 조정: 처음 계획은 단계 4 하나였다. 2026-11-05에 학생이 단계 3처럼 둘로 나누기로 했고, 2026-11-06에 이 이슈를 4-1로 고쳐 쓰기로 했다. 4-2(Animator 재생과 스키닝)는 별도 이슈다.

- 포함: AssetManager(glTF 읽기, 경로로 원본 공유, 읽기 쉬운 오류), 외부 로더 cgltf 소스 한 벌과 라이선스, 좌표계 변환(오른손·반시계 → 왼손·시계 방향 앞면), 저장소 안의 작은 시험 모델, Scene의 tick 끝 반영, C++20 전환.
- 제외: 재생·스키닝·뼈 행렬(4-2), 텍스처와 재질(색은 지금처럼 ModelRenderer가 정한다), 실행 중 원본 내리기, FBX·다른 형식, 큰 팀 에셋의 저장소 커밋.

## 모듈 계약

- **AssetManager**: 경로를 받아 glTF 파일을 읽고 `ModelData`를 만든다. 같은 경로를 다시 요청하면 이미 읽은 원본을 돌려준다. 원본은 프로그램이 끝날 때까지 갖고 있고 실행 중에 내리지 않는다. Application이 소유하며, Renderer와 Scene보다 먼저 선언해 더 오래 산다(Renderer가 원본 주소로 GPU 버퍼를 기억하기 때문이다).
- **ModelData**: 모델 파일 하나에서 나온 CPU 원본. 메시(정점·인덱스, 엔진 좌표계로 바꾼 뒤), 뼈 개수, 클립 이름 목록. `MeshData`는 3-2 그대로다.
- **ModelRenderer**: 3-2처럼 `MeshData` 주소를 가리킨다. 불러온 모델도 `ModelData` 안의 `MeshData`를 가리키는 것뿐이라 컴포넌트는 바뀌지 않는다.
- **호출 시점**: Application이 Initialize에서 장면을 만들기 전에 한 번 읽는다. 게임 도중에는 읽지 않는다. 컴포넌트는 AssetManager를 모른다. Scene이 알려 주는 서비스는 Input·Time 둘 그대로다.
- **오류**: 없는 파일, glTF가 아닌 파일, 지원하지 않는 데이터(삼각형이 아닌 그리기 방식, 위치가 없는 정점 등)는 경로와 이유를 담은 예외로 보고한다. main이 받아 `Error: ...`로 찍고 종료 코드 1을 낸다. 3-2의 오류 규칙과 같다.
- **tick 끝 반영**: Application이 tick 시작과 끝을 Scene에 알린다. 그 사이에 요청된 생성·삭제·Clear는 tick 끝에 한꺼번에 반영한다. tick 밖(Update, 시험 코드)에서는 지금처럼 Update 끝의 안전장치와 즉시 반영이 남는다.

## 완료 조건

- [ ] 저장소 안의 작은 시험 모델이 창 모드에서 Player 자리에 바인드 포즈로 보인다. 좌우가 구분되는 모양이라 거울처럼 뒤집히지 않았는지 눈으로 확인할 수 있다.
- [ ] 같은 원본을 두 객체가 공유한다. 원본은 한 번만 읽고 GPU 버퍼도 한 벌이다.
- [ ] 없는 파일, glTF가 아닌 파일, 지원하지 않는 데이터가 경로와 이유가 적힌 오류로 보고된다.
- [ ] 변환한 메시가 엔진 규칙(왼손, 시계 방향 앞면, 바깥을 보는 법선)을 지키는지 CPU 시험이 확인한다.
- [ ] tick 안 어느 단계에서 생성·삭제·Clear를 요청해도 tick 끝에 반영되고, 그 전까지 객체를 차례로 도는 단계가 끊기지 않는다.
- [ ] 설계 검증 보고서(단계 4 전환)의 반드시 정할 것 3개(tick 끝 반영 구간과 생성 규칙, 원본 소유·수명과 캐시 열쇠, 좌표계 변환)가 단계 문서에 적혀 있다.

## 학생 질문과 과제

1. AssetManager가 가진 원본과 ModelRenderer가 가리키는 것은 무엇이 다른가? 객체 하나를 지우면 무엇이 남는가?
2. glTF의 삼각형을 그대로 그리면 왜 뒷면이 보이는가? 로더가 무엇을 바꾸는가?
3. 생성·삭제 반영을 Scene.FixedUpdate 끝에서 tick 끝으로 옮기면 애니메이션 단계에 무엇이 보장되는가?

변형 과제: 같은 시험 모델을 가리키는 세 번째 객체를 다른 위치·크기로 추가하고, 원본을 읽는 로그가 몇 번 찍히는지 확인해 이유를 설명한다.
