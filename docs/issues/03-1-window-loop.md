# [단계 3-1] Win32 창과 DX11 장치, 실시간 루프

## 목표와 범위

Win32 창을 열고 창 메시지를 Input에, 실제 시계를 Time에 연결한다. DX11 장치와 스왑 체인을 만들어 화면을 한 가지 색으로 지우고 표시한다. 창 크기 변경, 최소화·복원, 닫기에 대응한다. 지금의 스크립트 데모는 `--demo` 검증 모드로 남긴다. 셰이더·도형·카메라·렌더 데이터는 단계 3-2에서 다룬다. 선행: 단계 2.

범위 조정: 처음 이슈는 단계 3 전체를 한 번에 다뤘다. 단계 전환 검증에서 한 PR로는 크다는 판단이 나왔고, 학생이 둘로 나누기로 정했다. 단계 3-2는 별도 이슈로 옮겼다.

## 모듈 계약

Window는 Win32 창과 메시지 처리를 맡는다. OS 키 코드를 Key로 바꿔 Input 수집 함수를 부르고, 창 크기·최소화·닫기 요청을 기록한다. Renderer와 게임 행동은 모른다. Renderer는 DX11 장치, 스왑 체인, 화면 대상을 소유하고 정리한다. Application은 Input, Time, Window, Renderer, Scene을 이 순서로 소유하고, 메시지 처리가 끝난 뒤 크기 변경을 Renderer에 전달한다.

## 완료 조건

- [ ] 인자 없이 실행하면 창이 열리고, 창을 닫으면 정리한 뒤 종료한다.
- [ ] 키보드로 Player 위치가 바뀌는 것을 로그로 확인한다.
- [ ] 창 크기 변경, 최소화, 복원에서 멈추지 않는다. 최소화된 동안 게임 시간이 멈춘다.
- [ ] 포커스를 잃으면 이동이 멈추고, 돌아온 뒤에는 키를 다시 눌러야 움직인다.
- [ ] CI가 `--demo` 데모와 시험을 실행한다.
- [ ] 장치·스왑 체인·화면 대상의 소유와 정리 순서를 설명한다.

## 학생 질문과 과제

1. 창 메시지가 Input까지 도달하는 경로는 무엇인가?
2. 창이 최소화되거나 포커스를 잃으면 Input과 Time에는 각각 무슨 일이 일어나는가?
3. DX11 장치·스왑 체인·화면 대상은 누가 소유하고, 어떤 순서로 정리되는가?

변형 과제: 포커스를 잃었을 때도 최소화처럼 게임 시간이 멈추도록 바꾼다. 어느 파일에서 무엇을 바꿨는지, 정지가 언제 적용되는지 설명한다.
