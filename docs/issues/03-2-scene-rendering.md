# [단계 3-2] 카메라·도형·렌더 데이터로 장면 표시

## 목표와 범위

바닥·Player·Kraken을 단순 도형으로 화면에 그린다. 카메라 GameObject, ModelRenderer 컴포넌트, 프레임마다 Scene을 읽어 만드는 렌더 데이터, 셰이더, 깊이, 보간 계수를 다룬다. 범용 RHI·고급 재질·후처리·씬 에디터는 제외한다. 선행: 단계 3-1.

이 이슈는 처음 단계 3 이슈를 둘로 나눈 뒤쪽이다. 앞쪽은 단계 3-1 이슈에서 다룬다.

## 모듈 계약

Renderer는 GPU 리소스를 관리한다. Application이 모든 tick이 끝난 뒤 프레임마다 한 번 Scene을 읽어, 카메라·월드 변환·메시·색을 값으로 담은 렌더 데이터를 만들고 Renderer에 넘긴다. Renderer는 Scene을 읽지 않는다. 게임 행동 결정은 Renderer에 넣지 않는다.

## 완료 조건

- [ ] 바닥과 두 객체가 카메라·깊이를 적용해 표시된다.
- [ ] Transform 변화가 화면 위치에 반영된다.
- [ ] Time이 보간 계수를 주고, 렌더 데이터가 직전 tick과 현재 tick 사이를 보간한다.
- [ ] 렌더 데이터를 GPU 없이 시험한다.
- [ ] CPU 원본 데이터와 GPU 리소스의 소유와 정리를 설명한다.

## 학생 질문과 과제

1. GameObject의 위치가 화면에 도달하는 경로는 무엇인가?
2. 카메라와 Renderer는 어떤 관계인가?
3. CPU 원본 데이터와 GPU 리소스의 소유자는 누구인가?

변형 과제: 카메라 위치를 바꾸고 같은 월드 좌표의 객체가 어떻게 보이는지 설명한다.
