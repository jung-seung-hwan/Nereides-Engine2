# [단계 4-3] Animator 재생과 스키닝

## 목표와 범위

4-1에서 읽은 모델 원본의 클립을 객체마다 따로 재생한다. Animator 컴포넌트가 재생·반복·완료·기본 전환을 맡고, tick 안의 애니메이션 단계에서 포즈와 뼈 행렬을 계산한다. 뼈 행렬은 RenderFrame의 그리기 항목에 실려 셰이더가 정점을 뼈에 붙여 움직인다(스키닝). 정지·배속이 재생에 그대로 반영된다. 선행: 단계 4-2(SceneManager). 2026-11-09 학생 결정으로 SceneManager 단계가 4-2가 되어 이 단계는 4-3이다. Animator는 장면이 지워졌다 다시 만들어지는 것을 전제로 설계한다.

- 포함: 클립·뼈 계층·역바인드 행렬 읽기(4-1의 로더 확장), 정점의 뼈 번호·가중치, Animator(재생 시각, 반복, 완료, 기본 전환), 뼈 행렬 계산과 전달, 스키닝 셰이더, 포즈 보간 여부 결정.
- 제외: 리타게팅, 애니메이션 그래프 편집기, 여러 임포트 규격, 마커·판정 구간(단계 5).

## 모듈 계약

- 모델·클립 원본은 AssetManager가 공유하고, 재생 시각과 포즈는 Animator가 객체마다 가진다.
- Animator는 tick 안, Scene.FixedUpdate 뒤의 애니메이션 단계에서 `FixedDeltaTime()`만큼 진행한다. Update에서 진행하지 않는다. 그래야 단계 5의 판정과 같은 시계를 쓴다.
- Animator는 tick마다 이 tick의 시작 위치, 끝 위치, 반복 경계를 넘어 되감겼는지를 남긴다. 단계 5의 마커 판정이 그대로 쓴다.
- 뼈 행렬은 tick 안에서 계산해 둔다. 수집 함수는 읽기만 한다.
- 정점 형식에 뼈 번호 4개와 가중치 4개를 더한다. 셜록과 같은 모양이다.

정할 것(4-3 설계 문서에서 학생이 고른다): 포즈 보간(직전 포즈와 섞기 / 그릴 때 다시 샘플 / 50Hz 수용), 애니메이션 단계가 Animator에 닿는 길(Component 가상 함수 / 목록 / 형식 검사), 컴포넌트가 자기 Animator에 닿는 길(참조 넘기기 / GetComponent), "기본 전환"의 뜻(즉시 / 짧게 섞기).

## 완료 조건

- [ ] 시험 모델의 클립이 창 모드에서 재생되고, 반복·완료·기본 전환이 관찰된다.
- [ ] 정지·배속이 재생에 반영된다.
- [ ] 같은 원본을 쓰는 두 객체의 재생 시각을 독립적으로 바꿀 수 있다.
- [ ] 모든 뼈가 기본 자세일 때 스키닝 결과가 4-1의 화면과 같다.
- [ ] tick마다 남긴 시작·끝 위치와 되감김 여부를 CPU 시험이 확인한다.

## 학생 질문과 과제

1. 모델 원본과 Animator 상태를 왜 분리하는가?
2. 클립의 시간으로부터 뼈 자세와 화면이 어떻게 만들어지는가?
3. 공유 원본을 쓰는 객체 하나를 삭제하면 무엇이 남아야 하는가?

변형 과제: 같은 모델 두 개의 재생 시작 시점을 다르게 설정해 비교한다.
